# Portfolio Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a static, single-page, bilingual (PT/EN) portfolio site for Caio Sabino that presents his backend experience and production work to recruiters.

**Architecture:** One Next.js App Router page composed of six leaf section components. All copy lives in two typed dictionaries (`content/pt.ts`, `content/en.ts`) that satisfy a single `SiteContent` interface, so TypeScript makes a missing translation a build error. A client-side `LanguageProvider` swaps dictionaries and persists the choice to `localStorage`. No database, no API routes, no auth.

**Tech Stack:** Next.js (App Router, TypeScript), Tailwind CSS v4, shadcn/ui (`new-york`, Radix base), `lucide-react`, Geist Sans/Mono, deployed to Vercel.

**Spec:** `docs/superpowers/specs/2026-09-07-portfolio-site-design.md`

## Global Constraints

- **Dark theme only.** `<html className="dark">`. No theme switcher, no light-mode toggle.
- **Single accent — emerald.** Set once via the `--primary` / `--ring` CSS variables in `globals.css`. Never write a raw `emerald-*` Tailwind class in a component; always consume `bg-primary`, `text-primary`, `ring-ring`.
- **Surfaces come from tokens.** `bg-background`, `bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`. No ad-hoc hex values anywhere.
- **`--radius: 0.625rem`** throughout.
- **Content column:** `max-w-4xl`, centered, horizontal padding `px-6`.
- **Density:** comfortable — `p-6` / `gap-6`, body text `text-sm`.
- **Geist Mono is reserved** for dates, tech badges, section labels and metrics. Never for prose.
- **No phone number on the page.** The résumé PDF carries it; the public page does not. Email, GitHub and LinkedIn only.
- **No test framework.** Verification is `npx tsc --noEmit`, `npm run build`, and browser checks. Do not add Jest, Vitest, or Playwright.
- **Icons:** `h-4 w-4` inline, `h-5 w-5` standalone.
- **No animation library.** Scroll reveal is CSS-only and must be disabled under `prefers-reduced-motion: reduce`.
- **Every external link** carries `target="_blank" rel="noopener noreferrer"`.
- **Server and first client render must produce identical markup.** `localStorage` is read in an effect after mount, never during render.

- [ ] **Step 6: Fix the font hazard in `app/globals.css`**

`shadcn init` may have written `--font-sans: var(--font-sans)` — a circular reference that resolves to nothing, because Tailwind v4 resolves `@theme inline` at parse time and cannot see the variable Next.js injects at runtime. Inside the `@theme inline` block, the two font lines must read exactly:

```css
--font-sans: "Geist", "Geist Fallback", ui-sans-serif, system-ui, sans-serif;
--font-mono: "Geist Mono", "Geist Mono Fallback", ui-monospace, monospace;
```

- [ ] **Step 7: Set the emerald accent and radius in `app/globals.css`**

The spec calls the accent `--color-primary`; in the shadcn Tailwind v4 setup that name is produced by `@theme inline` mapping `--color-primary: var(--primary)`. So the value is set on `--primary`. Edit the **`.dark`** block (the only theme that ships) so these four lines read:

```css
--primary: oklch(0.696 0.17 162.48);
--primary-foreground: oklch(0.145 0 0);
--ring: oklch(0.696 0.17 162.48);
--radius: 0.625rem;
```

Set the same `--primary`, `--primary-foreground` and `--ring` values in the `:root` block too, so the accent cannot shift if the dark class is ever removed.

- [ ] **Step 8: Add the scroll-reveal keyframes to `app/globals.css`**

Append at the end of the file. The reduced-motion block is not optional.

```css
@keyframes reveal-up {
  from { opacity: 0; transform: translateY(12px); }
  to   { opacity: 1; transform: none; }
}

.reveal {
  animation: reveal-up 0.5s ease-out both;
  animation-timeline: view();
  animation-range: entry 0% cover 25%;
}

@media (prefers-reduced-motion: reduce) {
  .reveal { animation: none; opacity: 1; transform: none; }
}
```

- [ ] **Step 1: Create `lib/language-context.tsx`**

The stored preference is applied in an effect, never during render — reading `localStorage` in render would make the server HTML and the first client render disagree, which React reports as a hydration error.

```tsx
"use client";

import { createContext, useContext, useEffect, useState } from "react";
import type { SiteContent } from "@/content/types";
import { pt } from "@/content/pt";
import { en } from "@/content/en";

export type Language = "pt" | "en";

const STORAGE_KEY = "portfolio-lang";
const DICTIONARIES: Record<Language, SiteContent> = { pt, en };

interface LanguageContextValue {
  language: Language;
  setLanguage: (language: Language) => void;
}

const LanguageContext = createContext<LanguageContextValue | null>(null);

export function LanguageProvider({ children }: { children: React.ReactNode }) {
  const [language, setLanguageState] = useState<Language>("pt");

  useEffect(() => {
    const stored = window.localStorage.getItem(STORAGE_KEY);
    if (stored === "pt" || stored === "en") setLanguageState(stored);
  }, []);

  useEffect(() => {
    document.documentElement.lang = language === "pt" ? "pt-BR" : "en";
  }, [language]);

  function setLanguage(next: Language) {
    setLanguageState(next);
    window.localStorage.setItem(STORAGE_KEY, next);
  }

  return (
    <LanguageContext.Provider value={{ language, setLanguage }}>
      {children}
    </LanguageContext.Provider>
  );
}

export function useLanguage() {
  const context = useContext(LanguageContext);
  if (!context) throw new Error("useLanguage must be used within LanguageProvider");
  return context;
}

export function useContent(): SiteContent {
  return DICTIONARIES[useLanguage().language];
}
```

### Task 8: Full-page verification pass

Nothing new is built here. This task is the honest check that the page works as a whole, at both widths, in both languages — the things that only break once every section is present.

**Files:**
- Modify: only files where a defect is found

**Interfaces:**
- Consumes: everything from Tasks 1–7
- Produces: a page that satisfies the spec's verification criteria

- [ ] **Step 1: Add `scroll-behavior` and header offset**

Anchor links currently jump under the sticky header. In `app/globals.css`, add to the `html` rule:

```css
html {
  scroll-behavior: smooth;
  scroll-padding-top: 5rem;
}
```

Then wrap it so it respects the motion preference:

```css
@media (prefers-reduced-motion: reduce) {
  html { scroll-behavior: auto; }
}
```

- [ ] **Step 2: Verify every nav anchor**

Click each of the five nav links. Each target heading must land **below** the sticky header, not hidden behind it.

- [ ] **Step 3: Verify mobile at 375px**

In DevTools device mode at 375px wide: no horizontal scrollbar anywhere on the page; project cards stack; the header toggle stays reachable; no text is clipped or overlapping.

- [ ] **Step 4: Verify keyboard navigation**

Tab from the top of the page through to the footer. Every interactive element — nav links, the two toggle buttons, hero CTAs, social icons, the project link, all four contact cards — must show a visible emerald focus ring, and the order must follow the visual order.

- [ ] **Step 5: Verify reduced motion**

Enable "Emulate CSS prefers-reduced-motion: reduce" in DevTools rendering settings, then reload. Sections must appear immediately at full opacity — no fade, no movement — and anchor jumps must be instant. Confirm nothing is left invisible.

- [ ] **Step 6: Verify both languages end to end**

Read the whole page in PT, then toggle to EN and read it again. Every string must switch — no Portuguese left stranded in the English version. Reload and confirm the choice persisted. Check the console for hydration warnings one final time.

- [ ] **Step 7: Verify text contrast**

The spec requires WCAG AA. `text-muted-foreground` on `bg-background` carries most of the body copy, so it is the one at risk. Run Chrome DevTools → Lighthouse → Accessibility, and confirm no contrast failures are reported. If the muted token falls short, raise `--muted-foreground` in the `.dark` block until it passes — do not fix it by recolouring individual components.
